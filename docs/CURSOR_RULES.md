# Cursor — правила роботи з content-queue (v2)

Ти відповідаєш за ВСЮ організаційну частину Werba Way: файли, деплой, Notion, картинки, якість шаблонів вправ. Claude і Юра відповідають тільки за зміст. Стосується лише нових лекцій за форматом CONTENT_SPEC.md — старі лекції/вправи не займаємо.

## Тригер

Новий файл у `content-queue/lectures/pending/` або `content-queue/exercises/pending/` → обробляєш автономно, без запиту підтвердження на кожен крок (крім видалення/перезапису вже опублікованого).

## Картинки

- Усі `[IMAGE: keywords="...", alt="..."]` у тілі лекції та всі поля `image_keywords`/`header_image_keywords` у json — заміняєш на реальні зображення з безкоштовного стокового банку (Unsplash/Pexels API або еквівалент) за ключовими словами.
- Якщо за ключовими словами нічого пристойного не знайшлось — не публікуй, залиш у pending з приміткою в консолі, яке саме зображення не вдалось підібрати.
- Header image — окреме тематичне фото у шапці Notion-сторінки.

## Типи вправ — генератори

7 типів у шаблоні (5 старих LMS + `vocab-cards`, `picture-set`, `flip-task` — нові, додаються до існуючих, не замінюють):
`fill-in-blank`, `sentence-building`, `drag-and-drop`, `matching`, `vocab-cards`, `picture-set`, `flip-task` (+ старі 5 з LMS-коду).

Для кожного типу — **один еталонний шаблон/генератор**, який використовується для ВСІХ лекцій цього типу без варіацій верстки. Вимоги:
- Перед публікацією прогони автоматичну перевірку згенерованого HTML: усі інтерактивні елементи (drag&drop, flip-card, picker) working, немає розбитої розмітки, немає порожніх полів з json.
- Якщо валідація не пройшла — не публікуй, лог помилки в консоль, файл лишається в pending.
- `flip-task`: картка з переворотом — front показує `front_title`, back показує `back_scenario` + `back_checklist` як список.
- `picture-set`: 5–6 картинок, під кожною своє питання з json, окремий інпут для відповіді учня.
- `vocab-cards`: інтерактивні картки термін→визначення+приклад, час проходження орієнтовно 10–15 хв (не хардкодь таймер, просто відповідний обсяг).

## Notion-публікація

**КРИТИЧНО — синтаксис вбудовування вправ:** кожна вправа вставляється в Notion як РЕАЛЬНИЙ embed-блок (iframe), а НІКОЛИ як звичайне markdown-посилання. Правильний синтаксис Notion Enhanced Markdown:

```
<embed src="https://werba-way.vercel.app/embed/{lesson_id}/{exercise-type}">Підпис вправи</embed>
```

НЕПРАВИЛЬНО (так робити не можна, це виглядає як список посилань, а не урок):
```
[Otwórz vocab-cards](https://werba-way.vercel.app/embed/{lesson_id}/vocab)
```

Перед публікацією кожної сторінки — самоперевірка: чи є в контенті хоч одне `[Otwórz ...](` замість `<embed src="...">`? Якщо так — це баг, виправ перед тим, як вважати урок опублікованим.

Аналогічно для зображень: `[IMAGE: ...]` мітки заміняються на реальний `![Caption](URL)` (звичайний Notion image-блок), а не текстове посилання.

**Відео теж вбудовується, а не лінком:** `<video src="URL">Caption</video>` — реальний вбудований плеєр, ніколи `[текст](url)`.

**Якість зображень зі стокового банку — жорстке правило:** перед вставкою будь-якого зображення (header, inline, picture-set) перевіряй, чи немає на ньому видимого тексту, напису, шильди, водяного знаку чи інтерфейсних елементів будь-якою мовою. Якщо є — відхиляй і шукай інше за тими ж keywords. Якщо в json-файлі вправи є поле `image_constraints` — це обов'язкові додаткові критерії пошуку, використовуй їх завжди.

1. Парсиш frontmatter лекції, шукаєш `module` в `module_map.json` (ініціалізуй файл сам при першому запуску, якщо нема).
2. Створюєш/оновлюєш сторінку, вставляєш тіло без frontmatter, замінивши `[IMAGE: ...]` мітки на реальні зображення.
3. Форматування: заголовки, жирний для ключових термінів, емоджі точково (не в кожному реченні) — якщо в тексті від Claude їх забагато, це сигнал повернути на доопрацювання, а не самому редагувати зміст.
4. Перевіряєш нумерацію lesson_number на конфлікти в межах module — при конфлікті не перезаписуй, познач у `_manifest.json`.
5. Коли всі вправи уроку (vocab, picture-set, flip-task, grammar) опубліковані — вставляєш їхні iframe/embed у відповідні розділи сторінки в тому ж порядку, що в CONTENT_SPEC.md (читання→питання→словник→розмова→картинки→комунікація→граматика→підсумок→дз).
6. Homework-файл (`-hw.json`) публікується в кінці сторінки як окремий розділ "Домашнє завдання", включно з посиланням на відео/статтю (реальний URL від Claude — не перевіряєш його вручну, просто вставляєш).

## Деплой

- Кожен успішний цикл: `git add . && git commit -m "content: <lesson_id>" && git push`.
- CI/CD (Vercel/GitHub Actions) тригериться пушем автоматично.

## Чеклист якості перед тим, як позначити урок "опубліковано"

- Жодного `[Otwórz ...](` в тексті сторінки — усі вправи мають бути `<embed src="...">`.
- Граматична таблиця — реальний Notion table-блок (`<table>...</table>`), не текст і не скріншот.
- Усі `[IMAGE: ...]` мітки замінені на реальні `![Caption](URL)`.
- Header cover — реальне зображення, не заглушка.
- Візуально відкрий сторінку (або опиши структуру) і зістав із CONTENT_SPEC.md: чи всі 10 розділів на місці і в правильному порядку.

## Жорсткі обмеження

- Не змінюєш зміст (текст, формулювання, питання, задачі) — тільки верстку/публікацію/картинки.
- Не публікуєш службові примітки, чернетки, TODO.
- Не видаляєш `published/` файли і не переписуєш `_manifest.json` заднім числом без явної команди Юри.
- Невалідний frontmatter/json або відсутні обов'язкові поля (image_keywords тощо) → не публікуй, залиш у pending з причиною в консолі.
- Це не твоя робота: писати чи редагувати зміст лекцій/вправ. Якщо бачиш сирий/незавершений контент у pending — не публікуй, повідом.
