## 4. Доступи і як їх отримати самому

Перевір на старті, які інструменти є в сесії.

### Notion + репо (норма)
Notion-конектор до воркспейсу Werba Way **і** push у GitHub `jurijteacher-cell/WerbaWay`.
→ Працюєш точно за LESSON_PROTOCOL: JSON у `src/content/queue-published/`, `python3 scripts/check_answers.py {lesson_id}`, сторінки сайту в `src/content/pages/` і `teacher-pages/`, push у `main` (Vercel деплоїть сам), запис у `content-queue/_manifest.json`, сторінки учня й TEACHER у Notion — рядками бази «Уроки» (id баз — у NOTION_STRUCTURE), fetch-перевірка, `python3 scripts/check_embeds.py --page … --remote`.

### Push дає 403 — підключи репо сам
Ознака: `git clone` працює, а `git push` дає `403 … not in this session's authorized repository set`.
→ `add_repo(owner="jurijteacher-cell", repo="WerbaWay", access="push")` → якщо `/home/claude/werbaway` уже є й `git rev-parse HEAD` працює — лише `register_repo_root` і повторити push; інакше `git clone --depth 1 https://github.com/jurijteacher-cell/werbaway /home/claude/werbaway` (таймаут ~10 хв) → `register_repo_root` → перенести свої коміти (`git format-patch` у старому клоні → `git am` у новому) → `git -c push.negotiate=true push origin HEAD:main`. Юрі патчі **не надсилати**.

### Інший акаунт без доступу до воркспейсу / репо
Ознака: Notion-конектор підключено не до воркспейсу Werba Way, `add_repo` відмовляє з причиною доступу.
→ Робиш усе, що можна в цій сесії (зміст, JSON, перевірка `check_answers.py`), пакет файлів уроку зберігаєш (`{lesson_id}-student.notion.md`, `-teacher.notion.md`, усі JSON — vocab, comm-tasks і hw обов'язкові) і одним рядком у чаті констатуєш, чого бракує сесії. Інструкцій Юрі не пишеш. Урок записуєш у §8 як «вправи не в main — відкрите для Claude».
