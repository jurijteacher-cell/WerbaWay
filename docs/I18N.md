# I18N.md — багатомовність Werba Way

Сайт і лекції працюють чотирма мовами: **укр · рос · пол · англ**. Перемикач у верхній
панелі, мітки текстові — прапорів немає ніде (прапор ≠ мова, а для російської це ще й
політично хибно).

Гілка: `i18n-multilang`, PR #3 у `jurijteacher-cell/WerbaWay`. Покриття перекладу
контенту — 100% усіма трьома мовами (6840 одиниць × 3). Словники інтерфейсу —
по 454 ключі на мову.

## Головне правило

**Польська не перекладається ніколи.** Вона цільова мова. Тексти лекцій, діалоги,
завдання, польські інструкції лишаються байт у байт. Мовою учня змінюється тільки
шар пояснення: глоси, підказки, коментарі про помилки, підписи, інтерфейс.

## Як визначається мова

`?lang=` → кука `ww_lang` → типова (укр).

Middleware зводить це в заголовок `x-ww-lang`, бо в Next `layout` не отримує
`searchParams`, а мову треба знати ще до рендера — для `<html lang>`, словника
й глос у лекції.

Ембеди відкриваються в iframe (Notion, клас), куди куки сайту не доходять, тому
туди мова йде параметром: `EmbedFrame` сам дописує `?lang=` в адресу вправи, а
`MockExam` і `PlacementTest` — у свої запити до API.

Вибір дублюється в `profiles.locale` (міграція `0015`), щоб їхав за учнем
на інший пристрій.

## Чому лекції не дублюються по мовах

Поряд із лекцією лежить **не копія**, а карта `{ ключ: "переклад" }`, де ключ
рахується з тексту джерела. Наслідки:

- правка польського тіла лекції не вимагає перекладати лекцію заново;
- неперекладена глоса просто лишається мовою джерела — сайт не ламається;
- один `.md` на всі мови, ніякого розсинхрону між чотирма копіями.

Сегментує по-простому: рядок таблиці ріжеться на комірки (глоси живуть саме там),
решта — цілим рядком. Перекладається лише те, що містить кирилицю. Переклад
комірки не може містити «|» або перенос рядка — інакше розірвало б таблицю.

## Польська локаль — окреме правило

Переклад глоси польською був би польською→польською. Тому в PL-локалі колонка
перекладу показує **коротке польське означення**:

`wynalazca` → `osoba, która wymyśla coś, czego wcześniej nie było`

## Контрастивні примітки адаптуються, а не перекладаються

«Ukraińskie *друг* to po polsku **przyjaciel**…» для російської стає
«Rosyjskie *друг*…», для англійської — «Angielskie *friend*…». Для англійської
пастка взагалі інша (`can` покриває і `umieć`, і `móc`), тому примітка
переписується, а не калькується.

## Конвеєр

```
node scripts/i18n-extract.mjs      # витяг одиниць із лекцій і вправ
node scripts/i18n-catalog.mjs      # дедуплікація → пакети на переклад
# переклад пакетів → src/content/i18n/_t/<locale>/batch-NNN.json
node scripts/i18n-apply.mjs        # розкладка по файлах
node scripts/i18n-check-batch.mjs ru 001   # перевірка повноти пакета
```

Для інтерфейсу: `i18n-ui-scan.mjs` (інвентаризація, `--dict` робить `uk.json`),
`i18n-ui-codemod.mjs` (загортання рядків у `t()`).

## Свідомі винятки

- **Назви властивостей у базах Notion** (`lib/embed-results/notion-sync.ts`) не
  перекладаються: це дані, переклад зламав би синхронізацію результатів.
- **Сторінки з англійськими поясненнями** (`pl-a0-en-*`, `ru-a0-*`) пропущені —
  вони вже написані під конкретну мову.
- **Старі лекції** в `src/content/lessons`, `src/content/lectures` — формат,
  з якого школа йде.
- **Сторінка діагностики** `/diag` — службова, для викладача.

## Що варто переглянути очима

- Таблиці «типових помилок»: перший стовпчик — фраза рідною мовою; у польській
  локалі він стає польським переказом сенсу («мені треба йти» → «mam obowiązek
  już wyjść»). Працює, але вправа від цього слабшає.
- Пояснення для англомовних на рівнях A0–A1: там машина має найбільше шансів
  схибити, а саме цю аудиторію ти продаєш через italki.
- Відносний час у дзвінку викладача («5 хв тому») лишився українським: це
  функція поза компонентом, без доступу до хука.

## Нові лекції

Щоб нова лекція одразу була багатомовною, після написання прогнати
`i18n-extract → i18n-catalog → переклад → i18n-apply`. Варто внести це
в LESSON_PROTOCOL як обов'язковий крок.
