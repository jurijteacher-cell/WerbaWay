### 0.4 Чому окремий канал `dock:<uid>`, а не наявний `class:<uid>`

`class:<uid>` несе «Дивитися учня» — присутність, `need-st`, знімки зі шматками й `ack`; ця логіка вже
мала зависання й петлі (див. коментарі в `useLiveChannel.ts`). Чат і дошка туди **не** підмішуються:
- новий приватний канал `dock:<uid учня>` з тими самими правилами доступу (викладач — будь-який, учень — лише свій);
- той самий websocket (supabase-js мультиплексує канали), тож це не друге з'єднання;
- `useLiveChannel` **не чіпати** (рішення Юри: «Дивитися учня» — окрема функція). Для `dock:` — новий хук `useDockChannel`
  з тим самим підходом (приватний канал, перепідключення 2→30 с, `ack`). Присутність у `dock:` — лише учня: `{path, pg, at}`,
  щоб чат і слова знали, в якій він лекції.
- Два `supabase.channel()` з однаковим topic в одній вкладці конфліктують → для `dock:` у вкладці один
  провайдер `<DockChannelProvider topic>` (React context), а чат і дошка підписуються через нього.

Міграція політик (додати до `0019`, нижче):

```sql
create policy "dock channel: receive" on realtime.messages for select to authenticated using (
  (select realtime.topic()) like 'dock:%' and realtime.messages.extension in ('broadcast','presence')
  and (public.is_teacher() or (select realtime.topic()) = 'dock:' || auth.uid()::text));
create policy "dock channel: send" on realtime.messages for insert to authenticated with check (
  (select realtime.topic()) like 'dock:%' and realtime.messages.extension in ('broadcast','presence')
  and (public.is_teacher() or (select realtime.topic()) = 'dock:' || auth.uid()::text));
```

Повідомлення в каналі `dock:` — одна подія `d`, тіло `{ k: … }` (типи — у новому `src/lib/dock/protocol.ts`).
Великі тіла (повний знімок дошки) — через наявні `toChunks` / `ChunkAssembler`.

### 0.5 Док — права панель

Один компонент `<ClassDock>` з вкладками **Чат · Слова** (у викладача) / **Чат** (в учня; слова учень бачить у чаті карткою і в `/words`).

- **ПК (≥1024 px):** панель 380 px праворуч, **зсуває** вміст сторінки (не перекриває лекцію). Ширину можна тягнути 320–560 px.
  Відкрита/закрита й ширина — у `localStorage` (`ww.dock`). Гаряча клавіша `Alt+C` (відкрити/закрити).
- **Вузький екран (<1024 px):** плаваюча кнопка 💬 праворуч унизу з лічильником непрочитаних → повноекранний аркуш
  знизу з кнопкою «Згорнути». (Юра працює з ПК; учні часто з телефона — їм теж має працювати.)
- Де живе: **учень** — на всіх сторінках, де зараз `LiveBeacon` (монтується в `TopNav`). **Викладач** —
  `/teacher/students/[id]` і `/teacher/students/[id]/watch` (там же, де «Дивитися учня»), розмова з цим учнем.
- На `/watch` док монтується **поруч** із `LiveWatch` у файлі сторінки (`page.tsx`); сам `LiveWatch`, `LiveBeacon`, `useLiveChannel`, `protocol.ts` — без правок.
  Тому замість рефакторингу `useLiveChannel` (§0.4) — **новий** хук `useDockChannel` (можна скопіювати підхід із перепідключенням).
- Вигляд — лише з `DESIGN_SYSTEM.md`: картка `ink-raised`, межа `ink-line`, радіус `--ww-r-lg`, вкладки як `.ww-steps`
  або сегмент, кнопки `.ww-btn-*`, поля `.ww-input`. Повідомлення: свої — `gold-fill` (бузкова наліпка, текст `paper`),
  чужі — `ink-soft`; час — `paper-faint`, `font-mono` 11px. Нові кольори не вигадувати.
- Кнопка дока в смузі заняття — елементом масиву `<Toolbar>` (правило §4 DESIGN_SYSTEM), не окремим блоком.
- Esc закриває аркуш на мобільному; фокус-контур видно; `aria-label` на кнопках-іконках.

## 1. Чат

### 1.1 Таблиця — міграція `0019_class_chat.sql` (наступний вільний номер)

```sql
create table public.class_messages (
  id           uuid primary key default gen_random_uuid(),
  student_id   uuid not null references public.profiles(id) on delete cascade, -- «кімната» = учень
  sender_id    uuid not null references public.profiles(id) on delete cascade,
  sender_role  text not null check (sender_role in ('teacher','student')),
  kind         text not null default 'text' check (kind in ('text','word','board','system')),
  body         text not null check (char_length(body) between 1 and 2000),
  meta         jsonb,               -- kind=word → {word_id}; kind=board → {action:'open'|'close'}
  lesson_slug  text,                -- лекція, в якій написано (null — «просто так»)
  page_idx     int,                 -- сторінка лекції на момент повідомлення (для «де це було»)
  created_at   timestamptz not null default now(),
  read_at      timestamptz,         -- коли прочитав ОДЕРЖУВАЧ
  deleted_at   timestamptz
);
create index on public.class_messages (student_id, created_at desc);
create index on public.class_messages (sender_role, read_at) where read_at is null;
alter table public.class_messages enable row level security;

create policy "chat: teacher all" on public.class_messages for all
  using (public.is_teacher()) with check (public.is_teacher());
create policy "chat: student reads own" on public.class_messages for select
  using (student_id = auth.uid());
create policy "chat: student writes own text" on public.class_messages for insert
  with check (student_id = auth.uid() and sender_id = auth.uid()
              and sender_role = 'student' and kind = 'text');
```

Позначка «прочитано» учнем — RPC `mark_chat_read()` (`security definer`, ставить `read_at = now()` на повідомлення
викладача в кімнаті `auth.uid()`, що ще не прочитані). Викладач — звичайний `update` (політика «teacher all»).
Час `created_at` ставить **сервер** (`default now()`), не клієнт.

### 1.2 Доставка

1. Відправник робить `insert … returning *` (через `@/lib/supabase/client`; RLS пильнує права).
2. Після успіху шле в `dock:<student_id>` `{k:'chat', m:<рядок>}`.
3. Одержувач додає повідомлення, відкидаючи дублікати за `id`.
4. Відкриття панелі / перепідключення каналу / повернення фокусу вкладки → `select` останніх 50 (`order by created_at desc`),
   злиття за `id`. «Показати раніше» — ще по 50 (курсор `created_at`).
5. `postgres_changes` **не** використовувати (broadcast уже є і не навантажує БД).
6. Відправка не вдалась → повідомлення лишається в стрічці сірим з «Не надіслано · Повторити».

### 1.3 Дата, час, лекція

- Під кожним повідомленням — `HH:MM` (локальний час того, хто дивиться, `Intl.DateTimeFormat` у мові інтерфейсу).
- Наведення / довгий тап → повна дата й час: «24 листопада 2026, 14:32».
- Роздільники днів: «Сьогодні» · «Вчора» · «24 листопада 2026».
- **Прив'язка до лекції:** `lesson_slug` ставиться автоматично —
  учень: якщо зараз на `/learn/<slug>[/hw]` (`lessonSlugOf(pathname)`) + номер сторінки (`pg` з `LessonPager`);
  викладач: лекція, в якій зараз учень — з легкої присутності учня в каналі `dock:` (`{path, pg}`), **не** з `LiveWatch`.
  Коли лекція змінюється між сусідніми повідомленнями — роздільник-чип «📖 53 · Z kim pracuję», клік відкриває лекцію.
- Фільтр над стрічкою: **Усі · Ця лекція** (друге — лише коли відкрита лекція).
- На `/teacher/students/[id]` в історії лекцій учня — посилання «Чат цієї лекції (N)» (фільтр за `lesson_slug`).

### 1.4 Поведінка

- Enter — надіслати, Shift+Enter — новий рядок; поле росте до 6 рядків.
- Текст — **лише як текст** (ніякого `dangerouslySetInnerHTML`); посилання `https://…` підсвічуються й відкриваються в новій вкладці (`rel="noopener"`).
- Польські літери, емодзі — без обмежень. Ліміт 2000 символів з лічильником від 1800.
- Викладач може видалити своє повідомлення (`deleted_at`, показується «повідомлення видалено»).
- Непрочитані: лічильник на кнопці дока; при відкритій панелі й видимій вкладці — одразу `read`.
  Тихий звук нового повідомлення — `<Switch>` «Звук» у шапці панелі, за замовчуванням увімкнено в учня, вимкнено у викладача.
- Викладач: `TeacherBell` отримує новий вид `chat` («Олена: Dzień dobry, mam pytanie…» → посилання на `/teacher/students/[id]` з відкритим доком);
  у списку `/teacher/students` — бейдж непрочитаних біля учня.
- Усі рядки інтерфейсу — через `t()` і в словники ru/pl/en того ж PR (`src/i18n/dict`).

## 2. Нові слова на занятті

### 2.1 Проблема

Колоди зараз — статичні файли `src/content/queue-published/<slug>-vocab.json` (`src/lib/words.ts → loadDeck`).
Слово, яке спитав один учень, — **його** слово, а не частина лекції для всіх. Отже — таблиця в БД, яка
**домішується** до колоди лекції тільки цьому учневі.

### 2.2 Переклад і приклад — варіанти

| | Як | Швидкість на уроці | Якість | Ціна |
|---|---|---|---|---|
| A. Вручну | Юра вписує слово + переклад (+ приклад) | повільно, відволікає | як напише | 0 |
| **B. AI-підказка (реком.)** | Юра вписує лише слово (польською **або** укр./рос. — «як буде „орендувати“?»), за 1–2 с з'являється заповнена картка: лема, частина мови/форми, переклад мовою учня, приклад рівня лекції + переклад прикладу. Юра правит будь-яке поле → Enter | 3–5 с на слово | добра; Юра бачить перед збереженням | ≈$0.0003/слово (gpt-4o-mini); 1000 слів ≈ $0.30 |
| C. Словник / DeepL | API перекладу | швидко | переклад є, **прикладів немає**, укр. часто немає у словниках | DeepL Free 500k симв./міс. |
| D. Гібрид «кинув і забув» | Слово зберігається одразу, AI дозаповнює у фоні, Юра перевіряє після заняття | 1 с | без контролю в моменті — помилка може дійти до учня | як B |

**Рекомендація — B**, з запасним шляхом A (немає ключа, тайм-аут 8 с, помилка → порожні поля вручну).
Ключ уже є в проєкті (`OPENAI_API_KEY`, `src/lib/openai.ts`, ним оцінюються відкриті відповіді) — перевірити, що він заданий у Vercel Production.

### 2.3 Таблиця — міграція `0020_student_words.sql`

```sql
create table public.student_words (
  id            uuid primary key default gen_random_uuid(),
  student_id    uuid not null references public.profiles(id) on delete cascade,
  lesson_slug   text check (lesson_slug ~ '^[a-z0-9][a-z0-9-]*$'), -- null → колода «Мої слова»
  term          text not null check (char_length(term) between 1 and 120),  -- як у колоді: «wynajmować»
  forms         text,   -- «czasownik ndk · wynajmuję, wynajmujesz · dk. wynająć»
  translation   text not null,
  tr_lang       text not null check (tr_lang in ('uk','ru','en','pl')), -- мова учня на момент додавання
  example       text,   -- польською
  example_tr    text,
  note          text,   -- коментар Юри (необов'язково)
  source        text not null default 'manual' check (source in ('ai','manual','ai-edited')),
  created_by    uuid not null references public.profiles(id),
  created_at    timestamptz not null default now(),
  deleted_at    timestamptz
);
create index on public.student_words (student_id, lesson_slug);
alter table public.student_words enable row level security;
create policy "words: teacher all" on public.student_words for all
  using (public.is_teacher()) with check (public.is_teacher());
create policy "words: student reads own" on public.student_words for select
  using (student_id = auth.uid() and deleted_at is null);
-- учень додає слова сам (§2.6a); вставка йде через API, яке ставить created_by = auth.uid()
create policy "words: student adds own" on public.student_words for insert
  with check (student_id = auth.uid() and created_by = auth.uid());
create policy "words: student edits own" on public.student_words for update
  using (student_id = auth.uid() and created_by = auth.uid())
  with check (student_id = auth.uid() and created_by = auth.uid());
```

### 2.4 API

- `POST /api/words/suggest` `{ studentId?, lessonSlug?, input }` → **нічого не зберігає**, повертає чернетку картки.
  Викладач — для будь-якого учня; учень — тільки для себе (`studentId` ігнорується, береться `auth.uid()`).
  Ліміт для учня: 60 підказок на добу (лічильник у таблиці або Upstash не потрібен — `count(*)` по `student_words`/журналу за 24 год),
  понад ліміт — ручний ввід. Мова перекладу — `profiles.locale` учня, тобто мова, яку учень сам вибрав на сайті
  (змінив мову — нові слова йдуть новою мовою; старі не перекладаються). Для `pl` — коротке польське означення.
  Рівень — `level` з frontmatter лекції (немає лекції → рівень з останньої пройденої, інакше A2).
- `POST /api/words` `{ studentId?, lessonSlug?, …картка }` (учень — лише для себе) → insert + повідомлення в чат `kind='word'`
  (`body` = «term — translation», `meta.word_id`) + broadcast `{k:'chat'}`. `source`: `ai` якщо не правили, `ai-edited` якщо правили, `manual`.
- `PATCH` / `DELETE /api/words/[id]` — правка й м'яке видалення: викладач — будь-яке слово, учень — лише свої (`created_by`).

Промпт для suggest (структурований вихід `response_format: json_schema`, `temperature: 0.2`, модель `gpt-4o-mini`, тайм-аут 8 с):
- Вхід може бути польською, українською, російською чи англійською; якщо не польською — дати польський відповідник.
- `term`: базова форма як у колодах Werba Way — дієслово в інфінітиві (+ видова пара в `forms`), іменник у N. lp. (+ рід), прикметник у ч. р.; стала фраза — цілою фразою.
- `forms`: частина мови польською (`czasownik`, `rzeczownik`, …) + 1–3 ключові форми, як у полі `part_of_speech` наявних колод.
- `example`: природне речення 6–12 слів на рівні лекції, побутовий/робочий контекст учня, без росієцентричного змісту; `example_tr` — переклад речення.
- Кілька значень (напр. «zamek») → найімовірніше в контексті лекції + `alternatives[]` з 1–2 іншими, які Юра може вибрати одним кліком.
- Нічого не вигадувати про форми, у яких модель не певна: краще порожнє `forms`, ніж неправильне.

## 3. Дошка

### 3.1 Суть

**Одна дошка Юри на всіх.** Юра відкриває її → поле як у Miro: стікери, текст, тягнути, масштаб. Вона зберігається на
сервері й переживає все (F5, закриття вкладки, інший пристрій, наступний день), **доки Юра не натисне «Очистити»**.
Глядачів Юра додає руками: «👥 Глядачі» → вибрав одного чи кількох учнів → вони бачать дошку наживо, **лише дивляться**.
Прибрав учня — у нього дошка зникає одразу. Кількох дошок, історії версій, збереження «на потім» — немає.

#### Зберігання й доступ — міграція `0021_teacher_board.sql`

```sql
create table public.teacher_board (
  id          int primary key default 1 check (id = 1),   -- рівно одна дошка
  els         jsonb not null default '[]',                -- BoardEl[]
  vp          jsonb,                                      -- в'юпорт Юри (для «Вести за мною»)
  follow      boolean not null default true,
  rev         bigint not null default 0,                  -- лічильник версій
  updated_at  timestamptz not null default now()
);
insert into public.teacher_board (id) values (1) on conflict do nothing;

create table public.board_viewers (
  student_id  uuid primary key references public.profiles(id) on delete cascade,
  added_at    timestamptz not null default now()
);

alter table public.teacher_board enable row level security;
alter table public.board_viewers enable row level security;
create policy "board: teacher all"   on public.teacher_board for all using (public.is_teacher()) with check (public.is_teacher());
create policy "board: viewer reads"  on public.teacher_board for select
  using (exists (select 1 from public.board_viewers v where v.student_id = auth.uid()));
create policy "viewers: teacher all" on public.board_viewers for all using (public.is_teacher()) with check (public.is_teacher());
create policy "viewers: self reads"  on public.board_viewers for select using (student_id = auth.uid());

-- канал дошки один: board:main. Слухати — викладач і поточні глядачі; писати — лише викладач.
create policy "board channel: receive" on realtime.messages for select to authenticated using (
  (select realtime.topic()) = 'board:main' and realtime.messages.extension in ('broadcast','presence')
  and (public.is_teacher() or exists (select 1 from public.board_viewers v where v.student_id = auth.uid())));
-- зміни дошки шле лише викладач; глядач може лише оголосити присутність (щоб Юра бачив, хто дивиться)
create policy "board channel: send" on realtime.messages for insert to authenticated with check (
  (select realtime.topic()) = 'board:main' and (
    public.is_teacher()
    or (realtime.messages.extension = 'presence'
        and exists (select 1 from public.board_viewers v where v.student_id = auth.uid()))));
```

- **Автозбереження:** клієнт Юри пише `els/vp/rev` в `teacher_board` з debounce 800 мс і обов'язково на `pagehide`/`visibilitychange` (через `fetch(..., {keepalive:true})` на API-маршрут). Під час уроку зберігається постійно, тож F5 нічого не губить.
- **Глядач** при відкритті читає `teacher_board` з БД (знімок), далі отримує `bd-ops` з каналу `board:main`. Юра не мусить бути онлайн, щоб глядач бачив останній стан.
- **Як учень дізнається, що його додали:** Юра додає глядача → у `dock:<uid учня>` іде `{k:'bd-invite'}` + повідомлення в чат `kind='board'` («Викладач відкрив вам дошку»). Прибрав → `{k:'bd-kick'}` у `dock:<uid>` і в `board:main`; клієнт учня закриває дошку й канал. Права Realtime перевіряються під час підключення, тож прибраний учень повторно підключитися не зможе (RLS).
- **Два пристрої Юри одночасно:** виграє останній запис (`rev`); пристрій, що отримав чужий `rev` вищий за свій, перезавантажує знімок. Конфліктів у межах одного користувача не розв'язуємо глибше.
- Ліміт: 300 елементів на дошці (далі «＋ Стікер» неактивний з підказкою «Очистіть дошку»), текст стікера ≤ 500 символів — щоб знімок і рендер на телефоні лишались легкими.

### 3.2 Бібліотека чи своє

| | За | Проти |
|---|---|---|
| tldraw | готове все | для продакшену потрібен ліцензійний ключ (без нього — водяний знак), ≈1 МБ |
| Excalidraw | MIT, малювання | важкий, стиль «від руки» не наш, стікерів як у Miro немає, синхронізацію однаково писати |
| **Своє (реком.)** | ~600–900 рядків, точно в DESIGN_SYSTEM, легкі повідомлення | писати самим |

Своє: DOM, не canvas. Контейнер `transform: translate(x,y) scale(z)`, елементи — `position:absolute` div-и, pointer events.
Маркер (v2) — SVG-шляхи через `perfect-freehand` (MIT, 3 КБ).

### 3.3 Модель

```ts
type BoardEl =
  | { id: string; t: 'note'; x: number; y: number; w: number; h: number; c: NoteColor; text: string; fs: 'S'|'M'|'L'; z: number }
  | { id: string; t: 'text'; x: number; y: number; w: number; text: string; fs: 'S'|'M'|'L'|'XL'; z: number };
type Viewport = { x: number; y: number; zoom: number };   // zoom 0.25–2
type NoteColor = 'violet' | 'sky' | 'pink' | 'mint' | 'lemon';
```

Кольори стікерів — **спершу додати в `DESIGN_SYSTEM.md` §1 і `globals.css`** токени `--ww-note-violet` (= `--ww-violet-fill`),
`--ww-note-sky` (= `--ww-sky-fill`), `--ww-note-pink` (= `--ww-pink-fill`), `--ww-note-mint`, `--ww-note-lemon`
(два останні — нові світлі відтінки, підібрати в гамі «холодний папір»), текст на всіх — `--ww-ink`, тінь — паперова `0 3px 0`.
Шрифт стікерів — Onest (читається з екрана учня), не Literata.

### 3.4 Що вміє Юра

- **＋ Стікер** (з вибором кольору) або подвійний клік по порожньому місцю → новий стікер, одразу в режимі вводу.
- **Т Текст** — підпис без фону (заголовки, приклади).
- Тягнути за тіло; кут — змінити розмір; подвійний клік — редагувати текст; Esc/клік поза — вийти з вводу.
- Виділення рамкою й Shift+клік → тягнути кілька; Delete — видалити; Ctrl+D — дублювати; Ctrl+Z / Ctrl+Shift+Z — 50 кроків.
- Розмір шрифту S/M/L на виділеному; зміна кольору стікера.
- Поле: тягнути порожнє місце або Space+тягнути — рух; Ctrl+колесо / пінч — масштаб; «Вмістити все».
- **👥 Глядачі** — спливне меню `.ww-menu`: пошук учня, список доданих з «✕». Видно, хто з глядачів зараз онлайн на дошці (присутність у `board:main`).
- **Вести за мною** (`<Switch>`, за замовчуванням увімкнено): учень бачить ту саму область і масштаб, що й Юра.
- **«Очистити»** — єдиний спосіб стерти дошку: підтвердження «Стерти всю дошку? Це не можна відновити» → `els = []`, `rev++`, `bd-full` глядачам. Список глядачів очищення не чіпає (окрема кнопка «Прибрати всіх»).
- «Згорнути» — дошка лишається як є, повертає до лекції; у смузі — чип «Дошка ●».

Відкривається з: окремої сторінки `/teacher/board` (пункт у меню викладача) і з `<Toolbar>` на `/teacher/students/[id]`
(«🧑‍🏫 Дошка» — там же одним кліком «Додати цього учня глядачем»). Займає весь екран над лекцією, док праворуч лишається.
Код «Дивитися учня» (`LiveWatch`) не змінюється; на сторінці `/watch` дошка лише доступна через той самий док/меню, без правок у `LiveWatch`.

### 3.5 Що бачить учень

- Юра додав учня глядачем → учневі поверх сторінки повноекранний шар «Дошка викладача» (коротка анімація появи) і чип «Дошка ●» у навігації, поки він глядач.
- Редагувати нічого не можна (жодних обробників, курсор звичайний).
- «Вести за мною» увімкнено → вигляд іде за Юриним (плавно, 150 мс); вимкнено → учень сам рухає й масштабує (пінч на телефоні), «Вмістити все».
- Кнопка «Згорнути» → дошка ховається, лишається чип «Дошка ●» (повернутися). Юра прибрав учня → шар і чип зникають самі.
- Учень зайшов/перезавантажився, будучи глядачем → знімок із БД + живі зміни; дошка відкривається сама лише першого разу після запрошення, далі — через чип.

### 3.6 Синхронізація

Канал `board:main` (живі зміни, шле тільки Юра) + `dock:<uid>` (запрошення/виключення конкретного учня).

| Повідомлення | Канал | Коли |
|---|---|---|
| `{k:'bd-invite'}` / `{k:'bd-kick'}` | `dock:<uid>` | Юра додав / прибрав учня (kick дублюється в `board:main` з `uid`) |
| `{k:'bd-ops', rev, ops}` — `{u: BoardEl}` / `{d: id}` | `board:main` | зміни; перетягування — ≤10/с (батч через rAF), фінальна позиція на `pointerup`; ввід тексту — debounce 250 мс |
| `{k:'bd-vp', vp}` | `board:main` | рух/масштаб при «Вести за мною», ≤10/с |
| `{k:'bd-full', rev}` | `board:main` | після «Очистити» — сигнал перечитати знімок з БД |

- Глядач тримає `rev`; прийшов `bd-ops` з `rev` ≠ свій+1 (пропуск через обрив) або перепідключився → перечитує `teacher_board` з БД.
- Ніхто не дивиться (немає глядачів онлайн за присутністю) → `bd-ops`/`bd-vp` не шлються, лише автозбереження в БД.
- Квота: Supabase **Pro** (5 млн повідомлень Realtime/міс. у тарифі). Типове заняття з дошкою ≈ 300–800 повідомлень — далеко від межі; тротлінг лишається, бо він і про плавність на слабких телефонах.

## 4. Мобільні — обов'язкова умова кожного PR

Юра: «усе інтегрувати для мобілок нормально, щоб нічого не крашилось». Мердж без цього розділу ✓ — заборонений.

**Що реалізувати**
- Лише **pointer events** (не mouse/touch окремо); жодна дія не залежить від hover. Те, що на ПК висить на наведенні
  («＋ у слова», видалити повідомлення, повна дата) — на телефоні через довгий тап (500 мс) → контекстне меню `.ww-menu`.
- Поля вводу з `font-size ≥ 16px` — інакше iOS Safari сам зумить сторінку при фокусі.
- Аркуш чату: висота від `window.visualViewport` (клавіатура не перекриває поле), `env(safe-area-inset-bottom)` для iPhone,
  блокування прокрутки сторінки під аркушем, прокрутка стрічки — `overscroll-behavior: contain`.
- Дошка: контейнер `touch-action: none`; пінч-масштаб і рух двома пальцями; без системного зуму сторінки під час жесту.
  Юра на планшеті/телефоні теж може редагувати: тап — виділити, тягнути — рух, подвійний тап — текст, довгий тап — меню (колір, розмір, видалити).
- Рендер дошки: позиції через `transform`, не `left/top`; оновлення в `requestAnimationFrame`; `React.memo` на стікері (перемальовується лише змінений).
- **Межі помилок:** `<ClassDock>` і `<Board>` обгорнуті в React error boundary — падіння всередині показує «Щось пішло не так · Перезавантажити панель», а **лекція й сторінка під ними продовжують працювати**. Помилку — в наявний `ReportBug`/лог.
- Мережа: обрив на телефоні (метро, перемикання Wi-Fi↔LTE, сон екрана) → тихе перепідключення з наростаючою паузою (як у `useLiveChannel`), при поверненні вкладки (`visibilitychange`) — догрузити чат і знімок дошки. Ніяких нескінченних циклів запитів.
- Пам'ять: у чаті рендеряться останні 200 повідомлень (старі — віртуалізація або «Показати раніше»), на дошці — ліміт 300 елементів.

**Як перевіряти**
- Playwright: додати проєкти пристроїв `iPhone 13` (WebKit) і `Pixel 7` (Chromium) у `playwright.config.ts`; тести `dock-chat`, `words`, `board` ганяються і на них.
- На preview очима (DevTools device mode мало — бажано реальний телефон через Vercel preview URL): ширини 360, 390, 768, 1024, 1440;
  поворот екрана; відкрита клавіатура; iOS Safari + Android Chrome.
- Нуль помилок у консолі під час тестів (тест падає на `pageerror`).

## 5. Ризики й сліпі зони

1. **«Дивитися учня»** не змінюється (рішення Юри): канал `class:`, `LiveBeacon`, `LiveWatch`, `/watch` — без правок. Наявні live-тести — умова мерджу PR-A як доказ, що нічого не зачепили.
2. **Помилки AI в словах** (неправильна форма, неприродний приклад) — попередній перегляд, позначка `source`, Юра бачить і слова, які додав учень, і може поправити.
3. **Учень і AI-підказки:** без ліміту хтось може «наклікати» витрати — ліміт 60/добу (§2.4).
4. **Мова перекладу** = мова, яку учень вибрав на сайті; змінив мову — старі слова лишаються попередньою мовою (переклад не переробляється).
5. **Одна дошка на всіх:** якщо Юра забуде прибрати глядача, той і далі бачить дошку, зокрема пояснення для наступного учня. Пом'якшення: у панелі дошки завжди видно список глядачів; кнопка «Прибрати всіх»; при відкритті дошки, якщо глядачі додані понад 12 год тому, — ненав'язлива підказка «Глядачі: Олена, Марко — прибрати?».
6. **Персональні дані в чаті** зберігаються безстроково — рядок про чат у `/privacy`; видалення акаунта стирає (`on delete cascade`).
7. **i18n:** нові рядки UI — у словники ru/pl/en у тому ж PR.
