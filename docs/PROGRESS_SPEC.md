# Werba Way — прогрес учнів у Supabase (v1)

Зона коду (Cursor/Claude Code). Автор контенту пише так, щоб він лягав у цю схему. Схема й функції — у міграції `supabase/migrations/20261001000000_werba_progress.sql` (перевірена на Postgres 16), Storage і Realtime — у `20261001000100_werba_storage_realtime.sql` (лише для Supabase, локально не перевірялася). Пізніші зміни (`page_progress`, `lesson_progress`, `0023`) — див. `SITE_PUBLISHING.md` §7.

## 1. Ідея

1. **Завдання — не файл, а рядок у базі.** Кожне завдання уроку отримує глобальний id `{lesson_id}:{item_id}` і тег граматики з реєстру. Прогрес рахується за тегами, а не за уроками, тож той самий тег, закріплений в уроках 21, 22 і 24, дає один показник «biernik-rzeczownik: 85%».
2. **Відповіді перевіряє сервер.** Ключі лежать у `course_item_keys`, учню недоступні. LMS шле відповідь у `submit_answer` і отримує фідбек. Зараз, якщо LMS читає JSON з відповідями у браузері, учень бачить їх у DevTools — це треба прибрати.
3. **Результати лише дописуються.** Кожна спроба — новий рядок. Прогрес, статуси й сигнали рахуються у view.
4. **Усне й письмо оцінює викладач** рубрикою 0–2 за критерієм. Аудіо лежить у приватному бакеті, його бачать лише учень і його викладач.

## 2. Таблиці

| Таблиця | Що в ній | Хто пише |
|---|---|---|
| `course_levels`, `course_modules`, `course_lessons` | структура курсу з карти | seed |
| `course_grammar_points` | реєстр тегів | seed |
| `course_can_do` | результати «Potrafię…» | seed |
| `course_items` | завдання без відповіді (`prompt` jsonb) | seed |
| `course_item_keys` | `answer`, `accept[]`, `explanation` | seed; читає лише викладач |
| `teachers`, `student_groups`, `group_members` | хто кого вчить | адмін / кабінет викладача |
| `lesson_runs` | одна сесія уроку: `class`, `homework`, `review`, `checkpoint`, `placement` | RPC |
| `item_attempts` | кожна спроба | RPC |
| `rubric_scores` | рубрики викладача | RPC `record_rubric` |
| `student_submissions` | посилання на аудіо або текст учня | учень (insert свого) |

Якщо в LMS уже є таблиці `students` / `profiles` / `lessons`, мапити на них (`auth.users.id` — спільний ключ), а не дублювати. Назви нових таблиць навмисно з префіксами, щоб не зіткнутися з наявними.

## 3. Доступи (RLS)

| Хто | Бачить | Може |
|---|---|---|
| Учень | курс без ключів, свої сесії, спроби, рубрики, записи | RPC для своїх сесій; завантажити свій запис |
| Викладач | усе про учнів своїх груп + ключі | створювати групи й додавати учнів; `record_rubric` лише своїм учням |
| anon | нічого | нічого |
| service_role | усе | seed курсу |

Перевірено тестами: учень не бачить ключів і чужих спроб, не може вставити спробу напряму, викладач не бачить чужих учнів і не може ставити їм рубрики чи додавати їх у свою групу.

## 4. Потік у LMS

```
відкрити урок      → rpc('start_lesson_run', {p_lesson_id, p_mode})         → run_id
відповідь          → rpc('submit_answer', {p_run_id, p_item_id, p_answer, p_duration_ms})
                     ← {correct, attempt_no, diacritics_hint, explanation, show_answer}
картка словника    → rpc('rate_vocab', {p_run_id, p_item_id, p_known})
кінець уроку       → rpc('finish_lesson_run', {p_run_id})                   → score
повторка           → rpc('get_review_items', {p_limit})  +  start_lesson_run(null, 'review')
рубрика викладача  → rpc('record_rubric', {p_student, p_task_kind, p_criteria, p_lesson_id, p_can_do_id, p_speaking_seconds, p_submission_id, p_comment})
```

**Як `submit_answer` перевіряє:**
- регістр, зайві пробіли, лапки й кінцева `.,!?` ігноруються;
- `accept[]` — додаткові правильні відповіді;
- `diacritics: lenient` (за замовчуванням) — відповідь без огонків зараховується, у відповіді приходить `diacritics_hint` з правильним написанням; `strict` — не зараховується;
- після двох помилок приходить `show_answer` (кнопка «Pokaż»);
- режими `checkpoint` і `placement`: одна спроба, у відповідь лише `{recorded: true}` — без правильності, підказок і ключа.

Для matching, drag-and-drop, true-false і multiple-choice відповідь — текст вибраного варіанта (`"true"` / `"false"` для true-false).

**Живий моніторинг:** викладач підписується на Realtime `INSERT` в `item_attempts`. RLS діє, тож приходять лише спроби його учнів.

## 5. Що рахується

| View | Що показує | Де використати |
|---|---|---|
| `v_first_attempts` | перша спроба кожного завдання в кожній сесії | база для всього нижче |
| `v_grammar_mastery` | за учнем і тегом: останні 10 перших спроб, % і статус | профіль учня |
| `v_skill_summary` | % за навичками за 30 днів: авто + рубрики | профіль учня, звіт батькам / учню |
| `v_can_do_status` | досягнуто / ні для кожного «Potrafię…» | сертифікат блоку, мотивація |
| `v_group_heatmap` | тег × група: середній %, скільки learning / mastered | кабінет викладача перед повторенням блоку |
| `v_alerts` | тег у статусі `learning`, хоча учень бачив його в ≥2 уроках | червоні позначки в кабінеті |

**Статуси тегу** (останні 10 перших спроб):

| Статус | Умова |
|---|---|
| `new` | менше 5 спроб |
| `learning` | менше 60% |
| `almost` | 60–79% |
| `mastered` | ≥80% і тег траплявся щонайменше у 2 уроках |

Правило «≥2 уроки» — навмисне: урок, де тег вводиться, не може сам по собі дати «mastered». Потрібне повторення, яке забезпечує карта курсу.

**Can-do:**
- `auto` — усі теги can-do в статусі `mastered`;
- `rubric` — остання рубрика з цим `can_do_id` ≥ `threshold` (70%).

**Повторка** `get_review_items`: завдання зі слабких тегів учня (`learning`, `almost`), лише з уроків, які він уже проходив, і які він не бачив 3 дні. Першими йдуть ті, де він помилявся. Це джерело для уроку 45 «Powtórka generalna», для уроку повторки після проваленої контрольної і для персональної домашки.

## 6. Seed: урок → база

`scripts/seed_lesson.py <папка уроку> --curriculum CURRICULUM_A0-A1.md` генерує SQL (upsert). Спершу запускається один раз для курсу (`--curriculum-only`: рівні, модулі, теги, can-do), потім для кожного уроку.

| Джерело | → | Куди |
|---|---|---|
| frontmatter `.md` | → | `course_lessons` (`published_at` ставиться лише з `--publish`) |
| `vocab.json` items | → | `course_items` `vocab-cards`, `skill=slownictwo`, `auto_scored=false` |
| `grammar.json`, `hw.json`, `exam.json`, `test.json` items | → | `course_items` + `course_item_keys` |
| `comm-tasks.json`, `pictures.json` | → | `course_items` з `auto_scored=false` (для статистики відкриттів; не оцінюються) |

- `prompt` = усі поля елемента, крім `id`, `grammar_point`, `answer`, `accept`, `explanation`. Для drag-and-drop туди ж копіюється `bank` блоку; для `t3`/`t4` — `source_text` / `dialogue` блоку.
- **matching:** ключ = `right`; у `prompt` — `left` і `pool` (усі `right` блоку, відсортовані). Інакше права частина потрапила б у браузер.
- `skill`: grammar → `gramatyka`; vocab і `grammar_point: slownictwo` → `slownictwo`; `exam_skill` блоку, якщо є.
- `diacritics`: `strict`, якщо блок має `"diacritics": "strict"`, інакше `lenient`.
- **Id не змінюються.** Якщо завдання з таким id уже має спроби, а його відповідь або тег змінилися, seed відмовляється й просить новий id. Старе завдання отримує `retired_at`.

## 7. Кабінет викладача (мінімум)

1. Група → теплова карта тегів (`v_group_heatmap`) → клік на тег → учні з `v_grammar_mastery`.
2. Учень → навички (`v_skill_summary`) + can-do (`v_can_do_status`) + записи «Głos przed / po» з рубриками.
3. Червоні позначки (`v_alerts`) на головній.
4. Форма рубрики: 5 критеріїв × 0/1/2 + `speaking_seconds` + коментар → `record_rubric`.

## 8. Ризики

- **Приватність.** Аудіо — це персональні дані. Потрібні згода при реєстрації, строк зберігання (пропоную 12 місяців після курсу) і видалення на запит. Для реклами — окрема письмова згода.
- **Учні з Preply.** Акаунт у LMS для учня з Preply — це інструмент уроку, а не канал продажу: жодних розсилок, оплат чи пропозицій групових курсів через LMS для цих учнів.
- **Списування.** На звичайних уроках учень може отримати відповідь після двох помилок і повторити сесію. На mastery це впливає мало (рахуються останні 10 перших спроб), а контрольні захищені режимом однієї спроби.
- **Локаль бази.** `lower()` для польських великих літер залежить від локалі. У Supabase вона UTF-8, це працює. Якщо базу колись перенесуть на `C`-локаль, варто перевірити.
- **Теги B1.** Уроки B1 (01, 02) мають власні теги поза реєстром A0–A1. Перед seed треба створити `CURRICULUM_B1` з реєстром або залити їхні теги в `course_grammar_points` окремо.

## 9. Тести

Що перевірено на Postgres 16 (29.09.2026):
- міграція лягає на чисту базу без помилок;
- ізоляція: учень не бачить ключів і чужих спроб, не вставляє спроби напряму; викладач бачить лише своїх; anon не викликає RPC;
- перевірка відповідей: регістр і крапка, `accept[]`, lenient / strict діакритика, `show_answer` після 2 помилок, режим checkpoint з однією спробою;
- `v_grammar_mastery`, `v_can_do_status`, `v_group_heatmap`, `v_alerts`, `get_review_items` на тестових даних;
- seed: карта курсу (42 теги, 25 can-do) і урок 21 (79 завдань, 42 з ключами); захист від зміни відповіді в завданні зі спробами; `retired_at` для видалених завдань; matching через `pool`.

`supabase/tests/werba_progress_test.sql` — сценарії на локальному Postgres 15+ із заглушкою `auth`: 2 викладачі, 2 учні, спроби, рубрики, ізоляція, повторка, режим контрольної. Файл сам підключає міграцію з `../migrations/`. Запуск із папки `supabase/tests`:

```bash
createdb werba_test
psql -d werba_test -f werba_progress_test.sql   # заглушка auth → міграція → сценарії; очікувані ERROR позначені в \echo
```

На продакшн-базі не запускати: тест створює користувачів і дані.
