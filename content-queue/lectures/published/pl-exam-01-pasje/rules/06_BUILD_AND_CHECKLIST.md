# 06 · Збірка (Claude Code) і чекліст перед видачею (Claude)

## Пайплайн (з 2026-10-31)

Claude у чаті проєкту → пакет файлів уроку + `BUILD_TASK_{id}.md` → Claude Code (хмарна сесія з доступом до репозиторію `jurijteacher-cell/werbaway`) кладе пакет у `content-queue/lectures/…/{id}/`, доробляє компоненти, перевіряє → гілка → preview на Vercel → Юра мерджить у `main` → LMS і Notion (embed).

Обидві ролі може виконати одна сесія: якщо в чаті є доступ до репозиторію, Claude пише зміст і сам збирає урок. Пуш — завжди в окрему гілку `claude/{id}-…`, не в `main`.

`{id}.md` — **не сторінка, а вихідник з маркерами.** Публікація = розгортання кожного маркера в компонент. Рядок `[IMAGE` / `[AUDIO` / `[SLIDES` / `[EXERCISE` в опублікованій сторінці = зламана збірка.

## Маркери

```
[IMAGE: keywords="…", image_keywords_alt="…", source="stock", alt="…"]
[AUDIO: id="…", source="teacher", text="section:1 | {file}#{item}.model_dialogue", plays="1"]
[SLIDES: file="{id}-slides.json", part="1"]
[EXERCISE: file="{id}-xxx.json", type="…", blocks="g1-g4"]
```
- Тіло `.md` не дублює вміст `.json` і не переказує презентацію: у розділах граматики — лише маркер і, за потреби, одне вступне речення.
- `blocks` — коли один файл ділиться між кількома місцями уроку.

## Слухання — читає вчитель (з 2026-10-31)

- **Аудіо не генерується.** Ні TTS, ні mp3 у `public/audio/`, ні полів `voice`, `audio_id`, `max_plays`, `audio_mode`.
- Маркер `[AUDIO]` завжди з `source="teacher"` → компонент `TeacherReads`: наліпка «Słuchaj — czyta nauczyciel» + скільки разів.
- Блок слухання в `exam` / `test` — `"audio_source": "teacher"`, `"reads": N`; `c1` — `"audio_source": "teacher"`.
- Учень текстів для читання не отримує взагалі: `stripTeacherTexts` (`src/lib/teacher-reads.ts`) вирізає `dialogue` з даних сторінки.
- Вчитель бачить тексти на тій самій сторінці з `?teacher=1` (`/lessons/{id}`, `/embed/{id}/exam`, `/embed/{id}/comm-tasks`) і в розділі «Тексти для читання вголос» файлу викладача.

## Зображення — Unsplash

- Тільки **Unsplash API**. `source` завжди `"stock"`. Історичні фото — вручну (`assets/manual/{id}-{slot}.jpg`).
- Зона Claude у змісті — лише ключі: 2–4 прості слова; alt — інша, простіша сцена. Ключі шапки й фото в Czytanie не збігаються.
- **Алгоритм збірки — без варіацій:**
  1. Є `{id}-images.lock.json` зі статусом `ok` → фото беруться з нього, запитів до API немає.
  2. Усі слоти уроку — паралельно; дедлайн 180 с на всі разом; після дедлайну незакриті слоти → `missing`.
  3. `GET https://api.unsplash.com/search/photos?query=…&per_page=10&orientation=landscape&content_filter=high`, заголовок `Authorization: Client-ID …` (ключ `UNSPLASH_ACCESS_KEY`), таймаут 10 с.
  4. **Перший** результат з `width >= 900`. Нічого не порівнювати.
  5. Порожньо / таймаут / помилка → один повтор з `image_keywords_alt` → знову нічого → `status: "missing"`, урок публікується. Максимум 2 запити на слот.
  6. `401` / `403` / `429` (демо-ключ: 50 запитів на годину) → усі незакриті слоти одразу `missing`, без повторів і очікування.
  7. Hotlink: `urls.raw + "&w=1200&fit=max&auto=format"` (`fit=max` не обрізає, `ixid` не видаляти). Файли до себе не завантажувати.
  8. Один `GET links.download_location` на кожне взяте фото (таймаут 5 с, помилку ігнорувати).
  9. Підпис: `Photo: {user.name} / Unsplash`, посилання на автора й на unsplash.com з `?utm_source=werba_way&utm_medium=referral`.
  10. Результат → `{id}-images.lock.json` (комітиться з уроком).

## Презентація

`public/slides/{lesson_id}.json` (без `teacher_note`) + `…teacher.json`; адреса учня `/slides/{lesson_id}`, викладача `?teacher=1`. У LMS — кнопка «Otwórz prezentację» + `iframe` 16:9.

## Межі збірки

Фото — 3 хв · одна зовнішня помилка — 1 повтор. Не шукати «кращий» кадр, не чіпати інші уроки й файли поза задачею. Зміст (тексти, відповіді, `grammar_point`, `accept[]`, слайди) під час збірки не переписується: помилка в змісті виправляється окремим кроком у пакеті й називається в звіті.

## DOM-контракт компонентів

Невидимі атрибути, на яких тримається e2e-тест. Кожен новий компонент робиться одразу з ними.

| Де | Атрибут |
|---|---|
| корінь блоку | `data-block-id` (для vocab / comm-tasks / pictures — `"vocab"`, `"comm-tasks"`, `"pictures"`) |
| закладка блоку | `data-role="tab"` + `data-target-block` |
| корінь елемента | `data-item-id` + `data-state="idle \| correct \| wrong \| correct-no-diacritics"` |
| поле вводу / «Sprawdź» | `data-role="answer-input"` / `data-role="check"` |
| варіант · штамп P/F | `data-role="option"` · `data-role="tf"`, обидва з `data-value` |
| matching | `data-role="match-left"` / `"match-right"` + `data-value` |
| drag-and-drop | `data-role="bank-word"` + `data-value` + `data-used`; `data-role="slot"` |
| пояснення | `data-role="explanation"` |
| слухання | `data-role="teacher-reads"` + `data-times`; текст для вчителя — `data-role="teacher-text"` (лише з `?teacher=1`) |
| картка | `data-role="flip"`; на корені `data-flipped="true"` |
| фото | `data-image-status="ok \| missing"`; `data-role="helper-question"` |
| слайди | `data-slide-id`; `data-role="teacher-note"` |

## Перевірка перед мерджем

Інструменти — у `tools/` цього архіву й у репозиторії (`scripts/`, `tests/`):

1. **`scripts/check_lesson_package.py <папка>`** — до збірки й після. Перевіряє JSON, id і префікси, `grammar_point`, варіанти й відповіді, банк drag-and-drop, `covers_slides`, слайди (прочерки, виділення, `refers_to`, пастки), маркери в `.md`, питання-опори, довжину діалогу, слухання (`audio_source: "teacher"`, `reads`, `dialogue`; жодних `voice` / `audio_id`), наявність `BUILD_TASK`. `ERROR` → збірку не починати.
2. `npx tsc --noEmit` і `npx next build`.
3. **`tests/lesson-exercises.spec.ts` (Playwright)** — e2e на локальному сервері або preview, керується JSON уроку. **Кожен елемент кожної вправи** отримує неправильну відповідь (має бути `wrong` і не блокувати), потім правильну (`correct`). Тест також перевіряє:
   - що `explanation` з'являється і всі `accept[]` зараховуються;
   - що відповідь без огонків дає `correct-no-diacritics`;
   - що кнопки `options[]` збігаються з JSON;
   - що слухання: учень бачить наліпку без тексту (і тексту немає в коді сторінки), вчитель з `?teacher=1` — текст;
   - що картки перевертаються, фото не обрізані (`object-fit` ≠ `cover`), у консолі немає помилок, а всі маркери розгорнуті;
   - що всі слайди відкриваються, а нотатки видно лише з `?teacher=1`.
4. Червоний тест через компонент → виправити компонент. Через зміст → виправити пакет і перепрогнати валідатор. Тест не підганяється під результат.
5. Ручний погляд на 390 px: закладки зверху, без горизонтального скролу.

Звіт — фіксованої форми (УРОК · ГІЛКА / PREVIEW · ПЕРЕВІРКА · ФОТО · ЗАЛИШИЛОСЯ · ПОМИЛКИ В КОНТЕНТІ), без переказу процесу.

## `BUILD_TASK_{id}.md` — обов'язковий у кожному пакеті

Коротко, без повторення правил. Еталон — `pl-exam-01-pasje`:

1. **Склад пакета** — таблиця файлів і типів.
2. **Заборони** — не міняти зміст, не підміняти типи, не чіпати інші уроки.
3. **Слухання** — таблиця «де · у даних · що бачить учень · що бачить вчитель».
4. **Фото** — слоти з ключами і статус.
5. **Перевірка** — команди запуску.
6. Форма звіту.

Пакет уроку містить `scripts/check_lesson_package.py` і `tests/lesson-exercises.spec.ts`. Claude проганяє валідатор сам до видачі пакета: пакет з `ERROR` не віддається.

## Чекліст Claude перед видачею пакета

**Структура**
- [ ] Cele lekcji (3–4) → розділи → Podsumowanie перевіряє кожну ціль і повертається до слова з розминки → Słowniczek.
- [ ] Обсяги тексту, словника, слайдів, блоків — за таблицею рівня.
- [ ] Текст оригінальний; є розминка, `[IMAGE]`, `[AUDIO source="teacher"]`.
- [ ] Кожна комунікаційна задача має ≥4 слова у своїй `comm_group`.
- [ ] `c1` має `model_dialogue` потрібної довжини з цільовою граматикою ≥4 рази і `audio_source: "teacher"`.

**Презентація**
- [ ] Повністю заповнена: жодних `___`, порожніх клітинок, «вгадай».
- [ ] Один слайд — одна думка; таблиці ≤6×6; поза таблицями ≤20 слів; ≤6 `[[...]]`.
- [ ] `teacher_note` українською на кожному слайді.
- [ ] Винятки тільки в `wyjatki` з `refers_to`; у теорії немає «wyjątek / oprócz / z wyjątkiem».
- [ ] 5–6 пасток, у кожній є українська форма.
- [ ] Жодного хибного «zawsze / nie ma».

**Вправи**
- [ ] Кожен слайд, крім титульного, є в `covers_slides`.
- [ ] Кожен елемент має `grammar_point` з frontmatter; неоднозначні — `accept[]` з усіма порядками слів.
- [ ] `e1` (6 тверджень, 3–4 хибні на деталях) і `e2` (дистрактори звучать у тексті для читання) — у форматі частин з `exam_focus`.
- [ ] Слухання: `audio_source: "teacher"`, `reads`, текст у кожному елементі або `source`; жодних `voice`, `audio_id`, `max_plays`.
- [ ] Id унікальні з префіксами; JSON валідний; лапки польські.

**Домашка й факти**
- [ ] Домашка не повторює ні речень, ні фактів, ні підтеми уроку; письмова тема ≠ питанням на говоріння.
- [ ] Письмо у форматі іспиту: звертання, закінчення, обов'язкові пункти, обсяг блоку курсу.
- [ ] Посилання перевірені або в чаті прямо сказано, що ні.
- [ ] Факти й приклади перевірені пошуком; приклади словника не з тексту.
- [ ] `recycles`: ≥6 слів і ≥1 граматична тема з двох попередніх уроків.

**Пакет**

- [ ] `BUILD_TASK_{id}.md` є, у ньому слухання, слоти фото з ключами й команди перевірки.
- [ ] `check_lesson_package.py` на пакеті — 0 `ERROR` (прогнано Claude до видачі).
- [ ] У пакеті є `scripts/check_lesson_package.py` і `tests/lesson-exercises.spec.ts`.
- [ ] Розбіжності з планом Юри й неперевірені факти названі в чаті.
