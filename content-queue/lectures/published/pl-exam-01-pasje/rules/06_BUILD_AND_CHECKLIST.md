# 06 · Збірка (Cursor) і чекліст перед видачею (Claude)

## Пайплайн

Claude → пакет файлів уроку + `CURSOR_TASK_{id}.md` → Cursor збирає → GitHub → Vercel (LMS + презентація) і Notion (embed).

`{id}.md` — **не сторінка, а вихідник з маркерами.** Публікація = розгортання кожного маркера в компонент. Рядок `[IMAGE` / `[AUDIO` / `[SLIDES` / `[EXERCISE` в опублікованій сторінці = зламана збірка.

## Маркери

```
[IMAGE: keywords="…", image_keywords_alt="…", source="stock", alt="…"]
[AUDIO: id="…", source="tts", text="section:1 | {file}#{item}.model_dialogue", voice="pl-PL-female", speed="0.9"]
[SLIDES: file="{id}-slides.json", part="1"]
[EXERCISE: file="{id}-xxx.json", type="…", blocks="g1-g4"]
```
- Тіло `.md` не дублює вміст `.json` і не переказує презентацію: у розділах граматики — лише маркер і, за потреби, одне вступне речення.
- `blocks` — коли один файл ділиться між кількома місцями уроку.

## Зображення — Unsplash (уточнено 2026-10-15)

- Тільки **Unsplash API**. `source` завжди `"stock"`. Історичні фото — вручну (`assets/manual/{id}-{slot}.jpg`).
- Зона Claude — лише ключі: 2–4 прості слова; alt — інша, простіша сцена. Ключі шапки й фото в Czytanie не збігаються.
- **Алгоритм Cursor — без варіацій:**
  1. Є `{id}-images.lock.json` → фото беруться з нього, запитів до API немає.
  2. Усі слоти уроку — паралельно; дедлайн 180 с на всі разом; після дедлайну незакриті слоти → `missing`.
  3. `GET https://api.unsplash.com/search/photos?query=…&per_page=10&orientation=landscape&content_filter=high`, заголовок `Authorization: Client-ID …`, таймаут 10 с.
  4. **Перший** результат з `width >= 900`. Нічого не порівнювати, unsplash.com у браузері не відкривати.
  5. Порожньо / таймаут / помилка → один повтор з `image_keywords_alt` → знову нічого → `status: "missing"`, урок публікується. Максимум 2 запити на слот.
  6. `401` / `403` / `429` (демо-ключ: 50 запитів на годину) → усі незакриті слоти одразу `missing`, без повторів і очікування.
  7. Hotlink: `urls.raw + "&w=1200&fit=max&auto=format"` (`fit=max` не обрізає, `ixid` не видаляти). Файли до себе не завантажувати.
  8. Один `GET links.download_location` на кожне взяте фото (таймаут 5 с, помилку ігнорувати).
  9. Підпис: `Photo: {user.name} / Unsplash`, посилання на автора й на unsplash.com з `?utm_source=werba_way&utm_medium=referral`.
  10. Результат → `{id}-images.lock.json` (комітиться з уроком).

## Презентація

`public/slides/{lesson_id}.json` (без `teacher_note`) + `…teacher.json`; адреса учня `/slides/{lesson_id}`, викладача `?teacher=1`. У LMS — кнопка «Otwórz prezentację» + `iframe` 16:9.

## Компоненти — gate перед кожним уроком

Стан на 2026-10-14 (оновлювати після кожного звіту Cursor):

| Є | Немає |
|---|---|
| `vocab-cards`, `flip-task`, `fill-in-blank` (+`options[]`), `matching`, `drag-and-drop`, рушій презентації (у референсі) | `sentence-building`, `true-false`, `multiple-choice`, `picture-set`, аудіо-касета, блок цілей з чекбоксами |

Тип є в уроці, а компонента немає → **спершу компонент, потім урок.** Заборонено підміняти тип, прибирати блок чи рендерити його текстом.

## Таймбокси Cursor

Фото — 3 хв · одна зовнішня помилка — 1 повтор · увесь урок від архіву до preview — 20 хв. Не шукати «кращий» кадр, не йти в беклог, не чіпати файли поза задачею. Не переписувати зміст (тексти, відповіді, `grammar_point`, `accept[]`, слайди) — помилки в контенті йдуть у звіт для Claude.

## DOM-контракт компонентів (з 2026-10-15)

Невидимі атрибути, на яких тримається e2e-тест. Кожен новий компонент робиться одразу з ними.

| Де | Атрибут |
|---|---|
| корінь блоку | `data-block-id` (для vocab / comm-tasks / pictures — `"vocab"`, `"comm-tasks"`, `"pictures"`) |
| закладка блоку | `data-role="tab"` + `data-target-block` |
| корінь елемента | `data-item-id` + `data-state="idle \| correct \| wrong \| correct-no-diacritics"` |
| поле вводу / «Sprawdź» | `data-role="answer-input"` / `data-role="check"` |
| варіант · штамп P/F | `data-role="option"` · `data-role="tf"`, обидва з `data-value` |
| matching | `data-role="match-left"` / `"match-right"` + `data-value` |
| drag-and-drop | `data-role="bank-word"` + `data-value` + `data-used`; `data-role="slot"` |
| пояснення | `data-role="explanation"` |
| аудіо | `data-role="audio-play"` + `data-plays-left`; `disabled`, коли 0 |
| картка | `data-role="flip"`; на корені `data-flipped="true"` |
| фото | `data-image-status="ok \| missing"`; `data-role="helper-question"` |
| слайди | `data-slide-id`; `data-role="teacher-note"` |

## Перевірка Cursor перед публікацією (оновлено 2026-10-15)

Інструменти лежать у пакеті кожного уроку й у `tools/` цього архіву:

1. **`scripts/check_lesson_package.py <папка>`** — до збірки й після. Перевіряє JSON, id і префікси, `grammar_point`, варіанти й відповіді, банк drag-and-drop, `covers_slides`, слайди (прочерки, виділення, `refers_to`, пастки), маркери в `.md`, питання-опори, довжину діалогу. `ERROR` → збірку не починати.
2. Валідатор проєкту `scripts/validate_lesson.py`.
3. **`tests/lesson-exercises.spec.ts` (Playwright)** — e2e на preview, керується JSON уроку. **Кожен елемент кожної вправи** отримує неправильну відповідь (має бути `wrong` і не блокувати), потім правильну (`correct`). Тест також перевіряє:
   - що `explanation` з'являється і всі `accept[]` зараховуються;
   - що відповідь без огонків дає `correct-no-diacritics`;
   - що кнопки `options[]` збігаються з JSON — це ловить відомий баг дублювання;
   - що аудіо рахує `max_plays`, а після вичерпання кнопка гасне;
   - що картки перевертаються, фото не обрізані (`object-fit` ≠ `cover`), у консолі немає помилок, а всі маркери розгорнуті;
   - що всі слайди відкриваються, а нотатки видно лише з `?teacher=1`.
4. Червоний тест через компонент → виправити компонент (максимум 2 кола). Через зміст → нічого не виправляти, а записати у «ПОМИЛКИ В КОНТЕНТІ». Сам тест Cursor не змінює.
5. Ручний погляд на 390 px: закладки зверху, без горизонтального скролу.

Звіт — фіксованої форми (УРОК · PREVIEW · ЧАС · КРОК 0 · КОМПОНЕНТИ · ФОТО · АУДІО · МАРКЕРИ · ПЕРЕВІРКА UI · ЗАЛИШИЛОСЯ · ПОМИЛКИ В КОНТЕНТІ), без переказу процесу.

## `CURSOR_TASK_{id}.md` — обов'язковий у кожному пакеті

Без нього Cursor не починає збірку, а просить файл. Структура — як у `pl-exam-01-pasje` (еталон):

1. **Склад пакета** — таблиця файлів і типів.
2. **Заборони** — не міняти зміст, не підміняти типи, не шукати «кращі» фото, не чіпати інші уроки.
3. **КРОК 0** — пакет на місце + `check_lesson_package.py`.
4. **КРОК 1** — gate компонентів: таблиця «є / немає / що зробити» + DOM-контракт. Компоненти мають окремий таймбокс, у 20 хв уроку не входять.
5. **КРОК 2** — презентація: схема слайдів, адаптер замість правки JSON.
6. **КРОК 3** — фото: таблиця слотів з ключами + алгоритм Unsplash дослівно.
7. **КРОК 4** — аудіо: таблиця `audio_id` · текст · голос, швидкість.
8. **КРОК 5** — таблиця «маркер → розділ → компонент».
9. **КРОК 6** — перевірка з командами запуску.
10. Таймбокси і форма звіту.

Пакет уроку містить `scripts/check_lesson_package.py` і `tests/lesson-exercises.spec.ts`. Claude проганяє валідатор сам до видачі пакета: пакет з `ERROR` не віддається.
